# DirectX 12 GPU Compute from .NET — Lessons from the GpuProbe

> **Series:** [SPIR-V / Level Zero](SPIRV.md) · [SYCL / oneAPI](SYCL.md) · [DX12](DX12.md) · [OpenVINO](OPENVINO.md) · [ILGPU](ILGPU.md) · [ComputeSharp](COMPUTESHARP.md)

All findings below were verified on an **Intel Arc 140T** (8086:7DD1, 128 EU,
driver **1.15.37858**) running Windows 10.0.26200 and .NET 11.0 RC1. The DX12
leg of `tests/Nivara.GpuProbe` is a **hand-rolled, pure-P/Invoke path**: no
packages, no D3D12.NET / ComputeSharp / TerraFX, no Windows App SDK and no
Microsoft.Windows.SDK.NET projection — just `DllImport` + vtable-slot dispatch
against the inbox `d3d12.dll`, `dxgi.dll` and `d3dcompiler_47.dll`. It proves
managed .NET can drive D3D12 compute directly, and it is the measured
comparison leg to the SYCL/oneAPI path ([docs/SYCL.md](SYCL.md)) — HLSL `cs_5_1` DXBC is
compiled in-process, so there is **no external toolchain and no subprocess**.

---

## 1. What the leg proves

The same three production SmolLM-shaped BF16 kernels gate **PASS** on HLSL
`cs_5_1` against the production Nivara CPU kernels (CPU leg = gold), exactly
like the SYCL leg:

| kernel | gate vs CpuLeg (`\|leg − cpu\| ≤ 1e-6 + 1e-5·\|cpu\|`) | worst (diagnostic) |
|---|---|---|
| `dot16` (K=16) | **PASS** | 0.0 ULP (bit-exact) |
| `silu` (576) | PASS 576/576 | 4.0 ULP |
| `gemv` (1536×576) | PASS 1536/1536 | 14 336 ULP @ row 1508 (`\|diff\| = 1.6e-9`, near-zero ref row — f32 ULP is tiny there; the absolute gate passes with 600× margin) |

## 2. The compute pipeline (the canonical workflow)

`D3d12/D3d12Compute.cs` builds the whole pipeline from `DllImport`s. Every
vtable slot, GUID, enum and struct below was read from this machine's SDK
`10.0.26100.0\um\d3d12.h` — never from memory (memory-derived GUIDs were wrong
in three of seven cases) — and `ValidateLayouts()` asserts `Marshal.SizeOf == C`
for every marshaled struct before running.

```
D3D12CreateDevice(adapter, FL 12_2)  ── level falls back 12_1/12_0/11_1/11_0
  │  (first DXGI adapter = the Arc; WARP has no FL 12_2)
  ▼
CreateCommandQueue (slot 8)  CreateCommandAllocator (slot 9)  CreateCommandList (slot 12)
CreateFence (slot 36, value 0)  CreateEvent (kernel32)
BuildRootSignature: D3D12SerializeRootSignature → CreateRootSignature (slot 16)
  └─ version 1.0: parameter 0 = SRV descriptor table at t0 (1 range),
                  parameter 1 = UAV table at u0 (1 range), all visibility
CreateDescriptorHeap (slot 14): CBV_SRV_UAV, 2 descriptors, SHADER_VISIBLE
  └─ GetDescriptorHandleIncrementSize (slot 15) = 64 on this driver
  └─ runtime identity check: heap->GetDevice (slot 7) must report our device,
     heap->GetDesc (slot 8) must report Type=0 / NumDescriptors=2 / Flags=1
  └─ GetCpuDescriptorHandleForHeapStart (slot 9) / GetGpu.. (slot 10)
GetDescriptorHandleIncrementSize (slot 15)

per kernel:
  D3DCompile(HLSL, entry, "cs_5_1", OPTIMIZATION_LEVEL3)   ← in-process, d3dcompiler_47.dll
  CreateComputePipelineState (slot 11) over a ComputePipelineStateDesc
  CreateCommittedResource (slot 27): UPLOAD input (GENERIC_READ) / DEFAULT output
    (UNORDERED_ACCESS + UAV flag) / READBACK output (COPY_DEST)
  CreateShaderResourceView (slot 18)  CreateUnorderedAccessView (slot 19)
  Map upload (slot 8) → copy packed BF16 → Unmap (slot 9)
  per pass (1 warmup discarded + 3 timed, best-of-3):
    Reset allocator (slot 8) → Reset list (slot 10) → SetComputeRootSignature (slot 29)
    → SetPipelineState (slot 25) → SetDescriptorHeaps (slot 28, 1 heap)
    → SetComputeRootDescriptorTable (slot 31) param 0 = SRV gpuHandle
    → SetComputeRootDescriptorTable (slot 31) param 1 = UAV gpuHandle
    → Dispatch (slot 14, groups) → ResourceBarrier (slot 26, UAV→COPY_SOURCE)
    → CopyBufferRegion (slot 15, DEFAULT→READBACK) → Close (slot 9)
    → ExecuteCommandLists (queue slot 10) → Signal (queue slot 14, ++value)
    → fence->SetEventOnCompletion (slot 9, value) → WaitForSingleObject(event)
  Map readback (slot 8) → read f32 → Unmap (slot 9) → release PSO + buffers
```

The fence advances monotonically (`NextFenceValue`); the event is a plain
auto-reset kernel event re-armed implicitly by the next `SetEventOnCompletion`
at a higher fence value.

## 3. HLSL kernel authoring (cs_5_1)

`D3d12/GemvKernels.cs` holds the three kernel sources as strings. The pattern:

```hlsl
StructuredBuffer<uint> gInput : register(t0);   // everything concatenated: [w | x]
RWStructuredBuffer<float> gOutput : register(u0);

float Widen(uint packed, uint element) {
    return (element & 1u) == 0u ? asfloat(packed & 0xFFFF0000u) : asfloat((packed & 0xFFFFu) << 16);
}

[numthreads(256, 1, 1)]
void CsGemv(uint3 dt : SV_DispatchThreadID) {
    if (dt.x >= Rows) return;
    float acc = 0.0f;
    for (uint k = 0; k < Cols; ++k)              // serial K loop = deterministic order
        acc += Widen(gInput[w >> 1], w) * Widen(gInput[(WeightElems + k) >> 1], WeightElems + k);
    gOutput[dt.x] = acc;
}
```

Rules that make this leg work:

1. **BF16 stays BF16 on the wire** — 2 bytes/element, byte-identical to the CPU
   and SYCL legs, packed two-per-`uint32` (element `2k` in the HIGH half,
   element `2k+1` in the LOW) so every element is an aligned load. The grid
   reads even/odd through `Widen(packed, element)`; `asfloat(bits << 16)` is
   the standard lossless BF16→f32 widen (BF16 is the upper half of f32).
2. **One thread per output row/element, serial K loop inside** — same
   determinism rule as the SYCL leg. The tolerance gate covers the honest
   reduction-order rounding vs the production CPU SIMD kernel.
3. **`[numthreads(N,1,1)]` with an `if (dt.x >= n) return;` guard** for
   non-multiple-of-256 shapes, `Dispatch(ceil(n/N), 1, 1)`.
4. **Single input SRV / single output UAV** — all inputs are concatenated into
   one `StructuredBuffer<uint>` so one root-signature binds the three kernels.
5. **`register(t0)` / `register(u0)`** must match the root-signature descriptor
   tables (parameter 0 → t register space, parameter 1 → u space).
6. **`cs_5_1` is plenty** for indexed structured buffers and `exp` — SM 5 is
   the floor for `StructuredBuffer` indexing on all D3D12 devices. SM 6.x
   (`WAVE_MMA`/DPAS BF16 dot) is a follow-up, see §6.

## 4. ABI / vtable gotchas that cost real debugging time

These are the hard-won rules of hand-rolled D3D12 from .NET. Get any of them
wrong and the probe AVs at the first call into the wrong slot.

### 4.1 Device vtable slots are `+4` over the naive method list

`ID3D12Device : ID3D12Object` (no `GetDevice`, no intermediate interface):
`IUnknown` = slots 0–2, `ID3D12Object` = slots 3–6 (`SetName`, `GetDevice`,
`GetPrivateData`, `SetPrivateData`), so `GetNodeCount` starts at **7**:

| slot | method | slot | method |
|---|---|---|---|
| 7 | `GetNodeCount` | 16 | `CreateRootSignature` |
| 8 | `CreateCommandQueue` | 17 | `CreateConstantBufferView` |
| 9 | `CreateCommandAllocator` | 18 | `CreateShaderResourceView` |
| 10 | `CreateGraphicsPipelineState` | 19 | `CreateUnorderedAccessView` |
| 11 | `CreateComputePipelineState` | 20–26 | (resources) |
| 12 | `CreateCommandList` | **27** | `CreateCommittedResource` |
| **13** | `CheckFeatureSupport` | 28–35 | (other) |
| 14 | `CreateDescriptorHeap` | **36** | `CreateFence` |
| 15 | `GetDescriptorHandleIncrementSize` | | |

The other interfaces used (all verified against the C-style vtbls in
`d3d12.h`): CommandQueue `ExecuteCommandLists`=10 / `Signal`=14 / `Wait`=15;
GraphicsCommandList `Close`=9 / `Reset`=10 / `Dispatch`=14 /
`CopyBufferRegion`=15 / `SetPipelineState`=25 / `ResourceBarrier`=26 /
`SetDescriptorHeaps`=28 / `SetComputeRootSignature`=29 /
`SetComputeRootDescriptorTable`=31; CommandAllocator `Reset`=8; Fence
`GetCompletedValue`=8 / `SetEventOnCompletion`=9 / `Signal`=10; DescriptorHeap
`GetDevice`=7 / `GetDesc`=8 / `GetCpuDescriptorHandleForHeapStart`=9 /
`GetGpuDescriptorHandleForHeapStart`=10; Blob `GetBufferPointer`=3 /
`GetBufferSize`=4; Resource `Map`=8 / `Unmap`=9.

**The original slot-15 `CheckFeatureSupport` was a false positive.** The probe
wrote 0x79 into a buffer and "read it back" — but slot 15 is a *UINT getter*
(`GetDescriptorHandleIncrementSize`) that never writes the probe buffer. A
UINT-returning sibling slot silently "succeeds"; only a call with a verifiable
side effect proves the slot. The current probe uses two: a bogus feature value
must return `E_INVALIDARG` (`0x80070057`) — which no other device slot does —
and a valid request writes a clamped reply.

### 4.2 Struct returns use a hidden pointer, not a register

`D3D12_CPU_DESCRIPTOR_HANDLE` / `D3D12_GPU_DESCRIPTOR_HANDLE` (8 bytes) and
`D3D12_DESCRIPTOR_HEAP_DESC` (16 bytes) are written through the x64 **hidden
return pointer**, not returned in RAX/RAX:RDX. This is empirically true for
this runtime (proven by `GetDesc` writing correctly through an `out` slot, and
by `GetCpu/GpuDescriptorHandleForHeapStart` AV'ing when declared as `long`/
`IntPtr` returns). The delegates **must** take an `out` parameter:

```csharp
[UnmanagedFunctionPointer(CallingConvention.StdCall)]
private delegate void GetGpuDescriptorHandleForHeapStart(IntPtr heap, out long handle);
// call: Vtable<GetGpuDescriptorHandleForHeapStart>(heap, 10)(heap, out long gpuStart);
```

An 8-byte-struct-as-`long` return *looks* right on paper and is the classic
first bug — verify with a 16-byte `out`-struct call (`GetDesc`) first, as the
probe's identity check does.

### 4.3 CheckFeatureSupport

`D3D12_FEATURE_SHADER_MODEL = 7` (feature 6 is `GPU_VIRTUAL_ADDRESS_SUPPORT`, a
16-byte struct — writing it into a 4-byte buffer overruns). Unknown shader
models are rejected with E_INVALIDARG, not clamped — so a sentinel "request
0x79 and watch it clamp" probe fails. The verified pattern: request a valid
model (6.8 = `0x68`) and require `hr ≥ 0` with a reply in `[0x50, 0x68]`,
**plus** the bogus-feature E_INVALIDARG negative control to prove the slot is
live. This driver reports **6.8**.

### 4.4 Everything else

- `D3DCompile` to `cs_5_1` via `d3dcompiler_47.dll` is safe — no `D3DCreateLinker`/
  `..Blob` COM dance; `D3DCompile` returns an `ID3DBlob`.
- Release discipline matters: device owned by `RunLeg`, released in `finally`;
  queue/allocator/list/fence/root-sig/heap owned by `ComputeContext.Dispose`;
  per-kernel PSO + buffers owned by a `ComScope`. Doubling a `Release` on a
  ref-counted COM object is a real crash source — each object has exactly one
  owner.
- `HeapProperties.CreationNodeMask = 1`/`VisibleNodeMask = 1` for committed
  resources (single-GPU node 0); `ResourceDesc.Layout = ROW_MAJOR` for buffers.
- UAV buffers (the DEFAULT output) need `ResourceFlagsAllowUnorderedAccess`
  (0x4) to be created; the READBACK copy target does not and must not.
- `SetDescriptorHeaps` takes a pointer-to-array of heap pointers (one here);
  `ExecuteCommandLists` takes a pointer-to-array of command-list pointers.

## 5. Performance — measured ranges vs the other legs

**All measured figures now live in the probe README's consolidated side-by-side
table** ([tests/Nivara.GpuProbe/README.md](../tests/Nivara.GpuProbe/README.md) → "Backend comparison — the numbers,
side by side"), which gathers the SYCL, DX12 and OpenVINO numbers into one
view. For this leg specifically (measured by
`dotnet run -c Release --project tests/Nivara.GpuProbe -- kernels`, best-of-3
within a run; ranges across runs capture GPU clock/power state): dot16 ran
117–560 µs, silu 86–364 µs, gemv 152–525 µs. CPU times are the production
Nivara kernels (`MatMulTransposedB`, `Activation.Silu`) via `CpuLeg.ComputeLeg`,
warmed once before timing.

Reading:

- **gemv is the headline everywhere.** Every SmolLM decode token is dominated
  by `[1536×576]·[576]` GEMVs; both the SYCL and DX12 legs run it at ~150-250µs
  vs ~2.3-2.5ms CPU — the 10-16× win is the phase's deliverable. SYCL vs DX12
  at gemv is within noise run-to-run (each wins some runs).
- **silu splits the two GPU legs.** SYCL (~12-21µs) beats the CPU loop
  (~30µs) ~2×; DX12 (~86-98µs) is ~3× *slower* than CPU at 576 elements —
  the DX12 leg's per-dispatch overhead (extra transition + copy + PSO) still
  dominates elementwise work this small.
- **dot16 is launch-bound** (correctness probe only): CPU 1.2µs, SYCL 13-21µs,
  DX12 117-131µs.
- These numbers share honesty caveats with SYCL.md: the DX12 leg recreates
  transient UPLOAD/DEFAULT/READBACK buffers and a fresh PSO per kernel, and the
  timing loop includes the record/barrier/copy/wait sequence — a production
  `src/Nivara.Gpu` would keep persistent buffers and pipeline a batch of
  kernels, removing the per-dispatch copy/transition overhead.

## 6. DXBC `cs_5_1` vs DXIL / SM 6.8 — and where WAVE_MMA fits

- **`cs_5_1` (DXBC):** what this leg compiles (`D3DCompile`, target
  `cs_5_1`). Fully supported by D3D12, gives indexed `StructuredBuffer`/UAV
  and `exp`. Zero tooling beyond the inbox `d3dcompiler_47.dll`.
- **DXIL (`cs_6_x`):** requires either `dxc.exe`/`dxil.dll` (not inbox; ships
  with the Windows SDK / some games / the DirectXShaderCompiler package) or
  `D3DCompile`'s successor API through `d3d12.dll`'s `D3D12CreateDevice`-adjacent
  piping. Not needed for these kernels — and the Arc reaches SM 6.8, but the
  **Wave Matrix / DPAS (BF16 FMA) instructions live at SM 6.8 + `WAVE_MMA`**
  with `SM6_8`-targeted DXIL (`WaveMatrix` intrinsics) or `DotUV4` variants.
- **Follow-up option:** an SM 6.8 `WAVE_MMA` BF16 dot-product path (the
  hardware DPAS unit) is where the real GEMM speedup lives; it needs a DXIL
  toolchain in-process (e.g. `D3DCompile2`/`D3D12ShaderCacheSession` preview
  APIs or `dxc.dll` load) and a `WAVE_MMA`-aware kernel — recorded, not yet
  built. The current `cs_5_1` path proves the whole pipeline (which is the
  point of this leg); DPAS is an optimization on top of it.

## 8. Verdict

**DX12 is a fully proven second compiler-backed GPU path.** A hand-rolled,
pure-P/Invoke D3D12 compute stack (no packages, no toolchain, HLSL compiled
in-process) gates all three production SmolLM kernels PASS against the
production Nivara CPU kernels, with gemv ~10-16× faster. It sits alongside the
SYCL leg ([docs/SYCL.md](SYCL.md)) as the measured comparison, and it is the natural
fallback backend when the SYCL runtime footprint is unacceptable — both bypass
the buggy IGC OpenCL/SPIR-V frontend (SYCL via compiler-produced SPIR-V over
Level Zero, DX12 via the driver's DXIL/DXBC frontend).
