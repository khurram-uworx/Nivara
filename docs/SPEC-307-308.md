# SPEC: Segmented Streaming for Non-Streamable Operations (#307, #308)

**Issues**: GitHub #307 (streaming falls back for window-heavy queries) + #308 (StreamingBufferManager not wired into execution path)

**Tier**: 2 (normal — behavioral fix + small feature)

**Isolation**: Feature branch `khurram/streaming-segments`. No worktree — the blast radius is limited to `StreamingExecutionStrategy.cs` and tests.

---

## Problem Statement

1. **#307**: `StreamChunksAsync` (used by `AsStream`) uses an all-or-nothing check — if any operation is non-streamable (Sort, Rolling, GroupBy, etc.) or contains a window expression, the ENTIRE plan falls back to a single materialized frame. The `Execute`/`ExecuteAsync` paths already have segment-aware streaming (`PartitionAtNonStreamableOps`), but `StreamChunksAsync` does not.

2. **#308**: The `MemoryBudget` in `NivaraExecutionContext` is advisory — it sizes the channel capacity but is never checked against accumulated memory. `StreamingBufferManager` (byte-level I/O budget) exists in Nivara.Extensions but is intentionally not wired into the core query pipeline (per STREAMING.md). The real enforcement gap is that accumulated frames in the consumer are never budget-checked.

## Approach

**For #307**: Port the segment-aware streaming from `Execute`/`ExecuteAsync` into `StreamChunksAsync`. Instead of falling back to a single frame, the pipeline will:
- Partition operations at non-streamable boundaries (reuse existing `PartitionAtNonStreamableOps`)
- Stream the leading streamable prefix per chunk (yielding one frame per chunk)
- At each segment boundary: accumulate all chunk frames, apply the boundary operation, yield the result as a single frame
- Resume streaming any trailing streamable operations per chunk

**For #308**: Add a `MemoryBudgetExceeded` diagnostic event to `ExecutionDiagnostics` that fires when accumulated chunk frames exceed the configured budget. This replaces wiring the I/O-layer `StreamingBufferManager` (which operates at a different abstraction level) with a direct budget check in the query pipeline.

## Acceptance Criteria (Gherkin)

### #307: Segmented Streaming

```gherkin
Feature: StreamChunksAsync segments non-streamable operations

  Scenario: Filter-only plan streams multiple chunks
    Given a chunked source with 2000 rows and chunk size 500
    And a plan with only a Filter operation
    When StreamChunksAsync is called
    Then at least 3 chunks are yielded
    And the total row count equals 2000

  Scenario: Filter then Sort yields streamable prefix + sorted frame
    Given a chunked source with 2000 rows and chunk size 500
    And a plan with Filter then Sort
    When StreamChunksAsync is called
    Then at least 1 chunk is yielded with Filter applied
    And a final frame is yielded with Sort applied
    And the total row count equals 2000
    And the Sort frame rows are in sorted order

  Scenario: Window expression in Select yields streamable prefix + windowed frame
    Given a chunked source with 2000 rows and chunk size 500
    And a Select operation containing RollingSum
    When StreamChunksAsync is called
    Then at least 1 frame is yielded (streamable prefix or window result)
    And the total row count equals 2000

  Scenario: All-non-streamable plan yields single frame
    Given a chunked source with 1000 rows
    And a plan with only a Sort operation
    When StreamChunksAsync is called
    Then exactly 1 frame is yielded
    And the frame contains all 1000 rows in sorted order

  Scenario: AsStream with non-streamable op yields more than one frame
    Given a CSV source with 1000 rows and a Sort operation
    When AsStream(chunkSize: 100) is called
    Then more than 1 frame is yielded (streamable prefix is chunked)
    And the total row count equals the Collect result

  Scenario: Results match LazyExecutionStrategy for mixed plans
    Given a chunked source with 5000 rows
    And a plan with Filter then Sort then Select
    When StreamChunksAsync is called and all frames are collected
    Then the combined result equals the LazyExecutionStrategy result
    And column values and null masks match exactly
```

### #308: Memory Budget Diagnostic

```gherkin
Feature: Streaming memory budget diagnostic

  Scenario: Budget check records diagnostic when chunks exceed budget
    Given a context with MemoryBudget = 500000 and ChunkSize = 1000
    And a chunked source that yields 20 chunks
    When ExecuteAsync completes
    Then ExecutionDiagnostics contains a budget-exceeded event if accumulated frames exceed the budget
    And the result is still correct

  Scenario: Budget is not exceeded with small datasets
    Given a context with MemoryBudget = 1GB and ChunkSize = 1000
    And a chunked source that yields 2 chunks
    When ExecuteAsync completes
    Then no budget-exceeded diagnostic is recorded
```
