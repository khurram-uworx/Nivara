# Plan — Fix QwenInstructParityTests FileNotFound when fixtures absent (#406)

## Problem

`tests/Nivara.Tests/AutoDiff/QwenInstructParityTests.cs` reads Torch reference fixture `.bin`
files via `ReadInt32`/`ReadFloat32` without an existence guard in two model tests:

- `Model_GreedyToolLoop_MatchesTorchGeneratedIds`
- `Model_GreedyFinalAnswer_SemanticParityAndFinalLogitsWithinTolerance`

When the checkpoint dir exists (7 files downloaded) but the reference generator
(`samples/NivaraInference/Python/qwen_tool_reference.py`) has NOT been run, the model loads but
the fixture bins are absent → `File.ReadAllBytes` throws **FileNotFound** and the tests **fail**
instead of skipping. The tokenizer tests and `Model_GreedyPlainPrompt_MatchesTorchGeneratedIds`
already guard with `Assert.Ignore`; these two do not. The model dir is gitignored, so this is a
local-developer scenario (checkpoint present, fixtures absent), not CI.

Fixtures read unguarded per test:

| Test | Fixtures |
|---|---|
| `Model_GreedyToolLoop_MatchesTorchGeneratedIds` | `qwen_tool_ids_py.bin`, `qwen_tool_prompt_ids.bin` |
| `Model_GreedyFinalAnswer_SemanticParityAndFinalLogitsWithinTolerance` | `qwen_tool_ids_py.bin`, `qwen_tool_final_prompt_ids.bin`, `qwen_tool_logits_py.bin` |

## Proposed changes

1. **Add fixture existence guards to the two tests** (primary fix), placed *before* the `Model`
   getter so the skip is cheap (avoids the ~1 GB model load). Mirror the file's existing pattern:

   ```csharp
   [Test]
   public void Model_GreedyToolLoop_MatchesTorchGeneratedIds()
   {
       var idsPath = Path.Combine(ModelDir, "qwen_tool_ids_py.bin");
       var promptIdsPath = Path.Combine(ModelDir, "qwen_tool_prompt_ids.bin");
       if (!File.Exists(idsPath) || !File.Exists(promptIdsPath))
           Assert.Ignore("Qwen tool greedy fixtures absent; skipping tool-loop parity verification.");
       ...
   }
   ```

   - `Model_GreedyToolLoop_MatchesTorchGeneratedIds`: guard `qwen_tool_ids_py.bin` + `qwen_tool_prompt_ids.bin`
   - `Model_GreedyFinalAnswer_SemanticParityAndFinalLogitsWithinTolerance`: guard
     `qwen_tool_ids_py.bin` + `qwen_tool_final_prompt_ids.bin` + `qwen_tool_logits_py.bin`

2. **Harden the plain-prompt test** (same-class latent hole, confirmed by user): add
   `qwen_plain_prompt_ids.bin` to the existing guard of `Model_GreedyPlainPrompt_MatchesTorchGeneratedIds`
   (currently guards only `qwen_plain_ids_py.bin` + `qwen_plain_logits_py.bin` but also reads
   `qwen_plain_prompt_ids.bin`).

3. **README note** (secondary remediation, confirmed by user): in
   `samples/NivaraInference/README.md` quick-start, next to the Qwen `hf download` line, note that
   the parity `.bin` fixtures are generated by `Python/qwen_tool_reference.py` /
   `qwen_plain_reference.py`, so checkpoint-only downloads don't silently skip parity.

**Design choice:** call-site guards rather than a guard inside `ReadInt32`/`ReadFloat32`.
Matches the file's established pattern, gives per-test skip messages, and skips BEFORE the
expensive model load. The helpers stay strict so genuinely-missing-but-expected fixtures still
surface as errors.
